# Claude Code + Codex + Grok 协作实施方案

版本 1.0，2026-10-25。适用于本仓库（41人投资观点研究台），也可平移到其他项目。

## 1. 结论先行

- 架构：**Claude Code 做主控**，Codex 和 Grok 以 MCP 工具的形式挂在 Claude 下面。不搭三个终端互相复制粘贴。
- 分三期上线，每期都有可量化的验收门槛，不达标就停在上一期，不上编排平台。
- 只依赖官方能力 + 本目录一个约 120 行的自建 Grok MCP 服务；社区桥接（grok-mcp、consult-mcp）和编排工具（MAO、Scout）只作为备选，未经验证不进主流程。

| 角色 | 工具 | 职责 | 何时调用 |
|---|---|---|---|
| 主控 | Claude Code | 拆任务、写计划、做架构决策、最终验收与提交 | 始终 |
| 执行 | Codex（`codex mcp-server`） | 按计划批量实现、跑测试、修到绿 | 计划已定、改动边界清楚时 |
| 情报 + 反方 | Grok（`grok_mcp.py`） | Web/X 实时检索、对抗式审查 | 需要最新信息，或合并前审查 |

本项目的具体价值：研究台跟踪的投资人大量在 X 上发言，Grok 的 X 检索可以直接补“公开线索”；但按项目规则，检索结果只能进线索队列，核验仍由人工完成。

## 2. 目录与交付物

```
docs/multi-agent/
  实施方案.md                本文
  grok_mcp.py               Grok MCP 服务（ask / search / review 三个工具）
  mcp.json.example          Claude Code 项目级 MCP 配置
  codex-config.toml.example Codex 侧挂 Grok 的配置
  AGENTS.template.md        两个 Agent 共用的项目规则
plans/                      第一期起创建，存放每个任务的计划文件
```

## 3. 第一期：共享规则 + 角色分工（第 1 周）

目标：不接任何桥接，先验证“Claude 写计划、Codex 实现”的手工交接是否比单用一个更好。

步骤：
1. 安装并登录两个 CLI：`claude`、`codex`，各自确认能在仓库内正常运行。
2. 把 `AGENTS.template.md` 复制为仓库根目录 `AGENTS.md`；新建 `CLAUDE.md`，内容 `@AGENTS.md`。这样两边读到同一份规则，避免漂移。
3. 建 `plans/` 目录。计划模板四段：目标 / 改动文件 / 验收标准（具体命令）/ 不做什么。
4. 流程：
   - Claude Code：`为<需求>写计划到 plans/2026-10-xx-<主题>.md，不要改代码`
   - Codex：`codex exec "按 plans/2026-10-xx-<主题>.md 实现，完成后运行验收命令"`
   - Claude Code：读 `git diff` 与测试输出，验收或打回。
5. 记录台账（见第 7 节）。

验收门槛：完成 ≥5 个真实任务；返工率不高于单用 Claude Code 时；测试 `python3 -m unittest discover -s tests -v` 与 `node tests/test_ui.cjs` 全绿。

## 4. 第二期：MCP 桥接（第 2–3 周）

目标：Claude Code 在一个会话里直接调用 Codex 和 Grok，去掉手工交接。

### 4.1 Codex 作为 MCP 工具

```bash
claude mcp add codex -- codex mcp-server
```

Claude 会获得调用 Codex 的工具（启动会话、继续会话）。建议在 AGENTS.md 中约定：Claude 只把“已写好计划的实现任务”交给 Codex，并传计划文件路径而不是长描述。

### 4.2 Grok 作为 MCP 工具

```bash
pip install "mcp>=1.2"
export XAI_API_KEY=...            # 放在 shell 配置或密码管理器，不进仓库
python3 docs/multi-agent/grok_mcp.py --smoke   # 先验证 API 可用
claude mcp add grok -- python3 docs/multi-agent/grok_mcp.py
```

也可以把 `mcp.json.example` 复制为仓库根目录 `.mcp.json`，团队共享配置（密钥仍走环境变量）。Codex 侧要用 Grok，把 `codex-config.toml.example` 合入 `~/.codex/config.toml`。

`--smoke` 失败时的处理：xAI 的模型名与搜索接口会变，改 `GROK_MODEL` 环境变量或 `grok_mcp.py` 中 `_search()` 的 payload，其余不动。

### 4.3 调用规则（写进 AGENTS.md）

| 场景 | 调用 | 不要调用 |
|---|---|---|
| 需要近 7 天的公开信息、X 上的表态 | `grok_search` | 用模型记忆回答时效性问题 |
| 计划定稿前的第二意见 | `grok_ask` 传计划全文 | 每个小改动都问 |
| 合并前审查 | `grok_review` 传 `git diff` | 传整个仓库 |
| 计划里 ≥3 个文件的机械性实现 | Codex | 需要架构判断的改动 |

单任务调用上限：Grok ≤3 次、Codex 会话 ≤2 个，超出说明计划没拆好，回到 Claude 重拆。

验收门槛：Claude 能在一个会话里完成“计划 → Codex 实现 → Grok 审查 → 验收”；Grok 审查在 10 个任务里至少发现 1 个真实问题（否则降级为只用检索）。

## 5. 第三期：编排层（第 4 周后，按需）

只有出现以下情况之一才上：
- 同时并行 ≥3 个任务，手工切换成为瓶颈；
- 需要定时、无人值守跑（例如每天 08:30 采集后让 Grok 检索新线索、Claude 汇总进简报）。

优先方案：Claude Code 无头模式 + 现有 Windows 计划任务（`install-daily-task.ps1`）调度，例如
`claude -p "读取 reports/ 最新简报，用 grok_search 补充关注名单近24小时 X 上的表态，写入 reports/<日期>-x-leads.md，只作线索"`。
MAO、Scout 等第三方编排工具先在独立分支试用一周，对比台账数据再决定。

## 6. 交接协议

跨模型只传三类结构化材料：
1. 计划文件路径（`plans/*.md`）；
2. `git diff`（必要时 `--stat` + 关键文件）；
3. 验收命令及输出。

禁止传完整聊天记录。Grok 返回的检索内容必须带链接；没有链接的结论不得写入数据文件。

## 7. 成本与效果台账

在 `plans/ledger.csv` 记录每个任务：

```
日期,任务,主控,Codex调用次数,Grok调用次数,返工次数,耗时分钟,审查发现真实问题数,备注
```

每周看一次：
- Grok 审查命中率 < 10% → 停用审查，只保留检索；
- Codex 返工率高于 Claude 自己实现 → 只把纯机械任务交给 Codex；
- 三方额度任一月度超预算 80% → 收紧第 4.3 节调用上限。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 密钥泄露 | `XAI_API_KEY` 只放环境变量；`.mcp.json` 用 `${XAI_API_KEY}` 引用；提交前 `git diff` 检查 |
| Grok 检索内容不准或过时 | 只进线索队列，带链接，人工核验，符合本项目“核验状态只由人工决定” |
| 规则在两个 Agent 间漂移 | 唯一规则源 AGENTS.md，CLAUDE.md 只做引用 |
| xAI 接口变更 | HTTP 细节集中在 `grok_mcp.py` 的 `_post` / `_search`，`--smoke` 先测 |
| 延迟变长 | MCP 只用于咨询节点，不放进高频工具循环 |
| 社区工具停更 | 主流程不依赖社区桥接 |

## 9. 时间表

| 周 | 交付 | 验收 |
|---|---|---|
| 1 | AGENTS.md、CLAUDE.md、plans/、台账 | 5 个任务走完手工交接，测试全绿 |
| 2 | Codex MCP 接入 | Claude 单会话完成计划→实现→验收 |
| 3 | Grok MCP 接入 + 调用规则 | `--smoke` 通过；10 个任务的台账 |
| 4 | 复盘 | 根据台账决定是否进入第三期 |

## 10. 待确认

- 主控是否确定用 Claude Code（本方案默认）；若改用 Codex 主控，把 Claude 以 `claude mcp serve` 挂到 Codex 下，其余不变。
- 是否需要第三期的定时 X 线索采集；需要的话再单独出计划，涉及数据流和人工复核节点。
